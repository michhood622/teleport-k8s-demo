# Teleport Kubernetes Take-Home: kubeadm, RBAC, Cert-Manager, and NGINX

This repository documents a reproducible Kubernetes lab built with Vagrant, Ubuntu 24.04, kubeadm, containerd, Flannel, ingress-nginx, Cert-Manager, and Kubernetes RBAC using certificate-based user access.

The goal is to demonstrate a standard Kubernetes installation with one control plane and two worker nodes, then deploy an NGINX application through a non-admin Kubernetes user with namespace-scoped permissions.

## Lab Topology

| Node | Role | IP | OS |
|---|---|---:|---|
| controlplane | Kubernetes control plane | 192.168.56.10 | Ubuntu 24.04 |
| node01 | Worker | 192.168.56.11 | Ubuntu 24.04 |
| node02 | Worker | 192.168.56.12 | Ubuntu 24.04 |

## What Vagrant Does

Vagrant only creates and prepares the three Ubuntu VMs. It does not install Kubernetes. The kubeadm installation is performed manually to keep the build aligned with the assignment.

Vagrant prepares:

- Hostnames and `/etc/hosts`
- Swap disabled
- Kernel modules for Kubernetes networking
- IP forwarding and bridge netfilter settings
- Per-node kubelet `--node-ip`
- Basic packages such as curl, git, vim, and openssl

## Quick Start

From your workstation:

```bash
vagrant up
```

SSH into each node and install containerd and Kubernetes packages:

```bash
vagrant ssh controlplane
sudo bash /vagrant/scripts/install-containerd.sh
sudo bash /vagrant/scripts/install-kubernetes.sh
```

Repeat on `node01` and `node02`.

On the control plane:

```bash
sudo kubeadm init \
  --apiserver-advertise-address=192.168.56.10 \
  --pod-network-cidr=10.244.0.0/16

mkdir -p $HOME/.kube
sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

Install Flannel and force it to use the Vagrant private interface:

```bash
bash /vagrant/scripts/install-flannel.sh
```

Join the workers using the command generated by:

```bash
kubeadm token create --print-join-command
```

Install ingress-nginx and Cert-Manager:

```bash
bash /vagrant/scripts/install-ingress.sh
bash /vagrant/scripts/install-cert-manager.sh
```

Configure RBAC and deploy NGINX:

```bash
bash /vagrant/scripts/configure-rbac.sh
export KUBECONFIG=$HOME/nginx-user.conf
kubectl apply -f /vagrant/kubernetes/nginx-deployment.yaml
kubectl apply -f /vagrant/kubernetes/nginx-service.yaml
kubectl apply -f /vagrant/kubernetes/certificate-nginx.yaml
kubectl apply -f /vagrant/kubernetes/nginx-ingress.yaml
```

## Validate

```bash
kubectl get nodes -o wide
kubectl get pods -A
kubectl get all -n web
kubectl get ingress -n web
```

Find the HTTP NodePort:

```bash
kubectl get svc ingress-nginx-controller -n ingress-nginx
```

Test:

```bash
curl -H "Host: nginx.local" http://192.168.56.10:<HTTP_NODEPORT>
```

## Key Lessons Learned

The most important troubleshooting issue in this lab was Flannel selecting `eth0` and advertising `10.0.2.15` for all nodes. In Vagrant/VirtualBox, `eth0` is the NAT interface and every VM receives the same NAT-side address. Flannel must use `eth1`, the private network interface carrying the `192.168.56.x` addresses.

The fix is included in `scripts/install-flannel.sh`:

```bash
kubectl -n kube-flannel patch daemonset kube-flannel-ds \
  --type='json' \
  -p='[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--iface=eth1"}]'
```
